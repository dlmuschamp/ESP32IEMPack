* What this is

A two-pack wireless in-ear monitor (IEM) prototype:

- *TX pack* — ESP32-WROOM + PCM1808 ADC captures line/stereo PCM and
  streams it over *ESP-NOW v2*.
- *RX pack* — ESP32-WROOM + PCM5102 DAC plays the stream into a headphone
  amp / IEMs.

This repo is the firmware (ESP-IDF, C, FreeRTOS) plus KiCad hardware
work. It is *not* a finished product UI — it is a bring-up of the audio
link.

* Findings (2026-08-21 sound-profile night) — CER summary

** Claim: Soft-LPF on *digital* audio is ruled out

- *Evidence:* ~RX_DAC_TEST~ sine_8k / chirp crisp; ~TX_TONE~ over air into
  shipping RX also crisp; direct laptop→IEMs bright.
- *Reasoning:* Known-bright PCM survives packing + ESP-NOW + PCM5102.
  Dullness that appears only with the real PCM1808 / jack path is not
  “ESP-NOW filtering highs.”

** Claim: Real-music dullness + buzz is analog / breadboard / level

- *Evidence:* Real music much quieter than digital tones; laptop <30% ≈
  noise; gain×8 louder but more crackle; 1 µF VIN caps marginal; shorter
  3.5 mm cable did not kill buzz; open GND dropped center (vocals/bass).
- *Reasoning:* Weak ADC level sits near the noise floor; Dupont / shared
  ground / breakout limits look like LPF+buzz. PCB layout is the next
  falsification — not more firmware EQ.

** Claim: TX_TONE steady ticks were mostly a FreeRTOS pace bug

- *Evidence:* ~pdMS_TO_TICKS(8)~ == 0 at ~FREERTOS_HZ=100~; RX queue drops
  flooded; ~esp_timer~ 7.5 ms pace fixed most ticks (code in
  ~main/testing/~).
- *Reasoning:* Shipping TX paces via blocking I2S reads; tone mode had
  to invent realtime pacing.

** Claim: Buzz may be a breadboard limitation (plus possible USB ground loop)

- *Evidence:* Persists with shorter cable; can improve when TX is on a
  power bank vs same-laptop USB+jack; digital path without ADC is clean.
- *Reasoning:* Ground loops and long analog jumpers are expected on a
  bench; a short-trace PCB with datasheet coupling/decoupling is the
  proper A/B.

* Hardware (bring-up)

** Roles

| Pack | MCU | Audio IC | Role |
|------+-----+----------+------|
| TX | ESP32-WROOM-32U (ext antenna) | PCM1808 | I2S master RX ← ADC |
| RX | ESP32-WROOM-32U (planned 32U + U.FL) | PCM5102 | I2S master TX → DAC |

** I2S notes that matter

- PCM1808 in slave mode wants *64 BCK/frame* → configure *32-bit stereo*
  Philips slots. 16-bit slots (32 BCK/frame) → silent ADC.
- MCLK ×256 is a valid PCM1808 ratio and matched our working builds.
  A casual jump to 24-bit data + MCLK×384 broke a known-good path —
  only revisit with a rollback bin ready.
- PCM5102: FMT low = I2S; DEMP low/NC = de-emphasis off.
- PCM1808 VIN: AC-couple with ~1 µF (TI app circuit; internal ~60 kΩ
  sets ~2.7 Hz HPF). Do *not* add an external 60 kΩ for that formula.

** Power (the lesson that unlocked pairing)

Marginal power on the TX pack looks exactly like "RF is broken":

- TX on weak battery → often never receives pairing ads.
- TX on laptop USB → pairs; opening ~idf.py monitor~ / pyserial can
  still *reboot* the board via CP2102 DTR/RTS → audio drops.
- Two decent USB power banks on *both* packs → instant pair, louder
  audio (more supply noise / crackle without caps).

For listening tests, prefer dedicated supplies. Use USB for flash and
short log peeks. Add bulk electrolytics + 0.1 µF at codec rails before
chasing "digital crackle."

* KiCad mapping notes (read before pouring copper)

Pack architecture (mechanical first): plastic shell ~Altoids *size* (not
metal tin). *ESP32-WROOM-32U* + external 2.4 GHz 50 Ω U.FL antenna —
*no DIY impedance matching* (module already brings 50 Ω to U.FL).
Antenna and volume pot on *opposite corners of the top face*; USB-C /
coiled battery power enter at the *bottom* (battery off-pack); 3.5 mm
IEM jack on a *side face*. Keep pot traces away from the antenna keepout.

** RX DAC / line toward pot (PCM5102)

- Open the *TI PCM5102 datasheet* and follow the *OUTL / OUTR* example
  aimed at a *LINE IN* into a *~10 kΩ* load — *page 27* (series R +
  shunt C network; same idea on both channels).
- Treat that filtered line node as *PRE_POT_IN_L / PRE_POT_IN_R* (not
  “headphone drive”).
- Feed PRE_POT into a *10 kΩ log dual-gang* pot; call the wipers
  *POST_POT_L / POST_POT_R* and drive the headphone amp from POST_POT.
- You may *ignore / delete* the older paper voltage-divider between
  ~dac_out_l/r~ and ~prepotL/R~ if page-27 LINEOUT already is PRE_POT_IN.
  Revisit only if levels still disagree after a clean PCB listen.

** Amp gain resistors (leave for later)

- On the paper desk schematic, resistors labeled *GROUP A* share one
  value; *GROUP B* share another; *A is not necessarily equal to B*.
- Leave GROUP A / GROUP B *unpopulated (DNP)* or hand-solder after
  listening — these set amp gain after you find ideal ratios. Do not
  freeze them in the first JLCPCB/PCBWay assembly BOM.

** TX ADC (PCM1808)

- Series *~1 µF* into VINL / VINR; AGND–DGND under the package; VREF /
  VCC / VDD local 0.1 µF (+ bulk where the datasheet shows).
- Match breakout reality: many modules already have rail caps; VIN
  coupling is what was often missing on the breadboard.

** Assembly / passives package size

- Default resistors and most ceramic caps to *0805* if you (or a first
  proto) will *hand-solder*. Still compact for an Altoids-sized pack;
  much easier than 0603/0402 with a normal iron + flux.
- *0603* is doable by hand with practice; *0402* is a pain — avoid for
  hand assembly.
- If a later JLCPCB/PCBWay full SMT run is the plan, 0603 (or denser)
  is fine for factory assembly; keep 0805 for DNP/hand-tweaked parts
  (e.g. GROUP A / GROUP B gain resistors) so you can change them on
  the bench.
- Modules that stay hard either way: ESP32-WROOM, USB-C receptacle,
  fine-pitch codecs — budget hot air / stencil or pay for PCBA on
  those, not “just upsize the passives.”

** Shipping firmware hygiene

- Production images: ~IEM_NODE=TX|RX~ only (~main/tx.c~, ~main/rx.c~).
- Isolation / peak-log / tone tools live under ~main/testing/~ — do *not*
  merge those diagnostics back into shipping sources for fab bring-up
  bins. Rebuild tests only when debugging.

* Firmware overview

** Build / flash (ESP-IDF)

~IEM_NODE~ is *configure-time*. Wrong node + stale build = wrong image
on the wrong pack.

#+begin_src bash
source ~/esp/esp-idf/export.sh   # or your IDF install

# Shipping transmitter / receiver
IEM_NODE=TX idf.py reconfigure build
IEM_NODE=TX idf.py -p /dev/ttyUSB0 flash

IEM_NODE=RX idf.py reconfigure build
IEM_NODE=RX idf.py -p /dev/ttyUSB0 flash

# Archived isolation builds (main/testing/)
IEM_NODE=RX_DAC_TEST idf.py reconfigure build flash
IEM_NODE=TX_TONE idf.py reconfigure build flash
IEM_NODE=TX_BUZZ_DEBUG idf.py reconfigure build flash
#+end_src

Stamped binaries (gitignored): ~firmware_out/~.

** Protocol sketch

1. RX advertises a short ~IEM_RX_…~ alias (broadcast, and unicast to last
   TX when known).
2. TX queues the request, ~esp_now_add_peer~, ACKs ~PAIR_SUCCESS~, then
   streams ~audio_packet_t~.
3. If ACKs are starved by audio, RX *soft-joins* on a correctly sized
   audio packet (app-layer proof of delivery).
4. TX may clear a dead peer on MAC send-fail / timeout so it can idle
   and accept a new advert.
5. Prefer not starting DAC playback on a lone 1-byte ~0x01~ ACK (any
   nearby ESP can spoof that and leave RX mute-and-not-advertising).

** FreeRTOS / dual core (what you bump into first)

- Wi‑Fi / ESP-NOW callbacks run in the Wi‑Fi task — keep them short
  (queue work; do not ~esp_now_add_peer~ / heavy I2S in the callback).
- Audio capture (TX) and playback (RX) are pinned to core 1 with a
  dedicated stack size (~AUDIO_TASK_STACK~).
- Pointer pools + FreeRTOS queues bound latency (drop-oldest under
  load) instead of unbounded buffering.

* Learning path (recommended order)

1. Blink / UART logging on ESP-IDF (prove the toolchain).
2. Square wave → PCM5102 (prove DAC + I2S pins).
3. PCM1808 capture → log peaks (prove ADC clocks / bit packing).
4. Tiny ESP-NOW ping, then grow to v2 payload size.
5. *Fix power* so both packs can transmit Wi‑Fi without brownout.
6. Pairing FSM + reconnect.
7. Digital tone isolation (DAC-only, then TX tone over air).
8. Only then: PCB layout / amp / timbre on a real board.

Reading datasheets is not optional on this project — the PCM1808 BCK
rule alone is a multi-hour footgun if you skip §serial audio interface.
