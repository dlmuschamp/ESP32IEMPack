* ESP32 Wireless IEM Pack

A first-pass wireless in-ear monitor (IEM) system: one ESP32 transmitter pack
and one ESP32 receiver pack (with support for up to 7 receiver packs).

- *RX path:* ESP-NOW -> ESP32 -> I2S -> PCM5102 DAC -> dual-gang volume pot ->
  MAX97220A headphone amp -> 3.5 mm jack
- *TX path:* TRS line-in -> PCM1808 ADC -> ESP32 I2S -> ESP-NOW to paired RX

*v1.0 boards are routed and quoted for fab* (JLCPCB Gerbers / BOM / CPL under
each =jlcpcb/production_files/=). Silk / cosmetic artwork may still change;
electrical intent for this spin is frozen. There is *no display on this version*
(a screen is a later idea, not this revision).

** First project --- how this happened

This is my first self-guided embedded systems project. Before late July 2026 I
had not written C for firmware, had not used ESP-IDF / FreeRTOS, had not read
audio or RF datasheets for a real build, and had never opened KiCad or laid out
a PCB. Pretty much everything that led to these boards was learned on the spot.

I started on a *breadboard with breakout boards* --- ESP32 modules, PCM5102,
amp, mess of jumpers --- without knowing if any of it would work. After a lot
of trial and error (wrong I2S slot formats, muted DAC, power noise, ESP-NOW
quirks), the breadboard path played audio. That proof is what made transferring
the design into KiCad worth doing.

The notes and "common mistakes" section below are the scars from that process.

Capacitor *types* to buy (ceramic vs polarized) by schematic location:
=docs/capacitor_bom.org=. PCM5102 on the RX is *PLL mode* (=SCK= to GND) with
I2S data from the ESP --- see that file.

** Firmware

All application code is *C*. It runs on *FreeRTOS* under *ESP-IDF*, using the
related Espressif libraries (ESP-NOW / Wi-Fi, I2S, ADC, LEDC, NVS). There is
*no hardware abstraction layer* --- the firmware calls ESP-IDF APIs directly.

- =main/tx.c= :: Transmitter. Done for this version (ESP-NOW, ADC pot,
  audio packet path).
- =main/rx.c= :: Receiver entry.  Also mainly done. Use =IEM_NODE=RX= when
  you flash it.
- =main/square_wave_test.c= :: Bench I2S tone used to prove the DAC path.
- =main/rig_shared.h= :: Shared packet and state types for TX and RX.

A packet sniffer / monitor node was an early idea. It is *not* part of this
version. It could come back later as a future extension (=IEM_NODE=MON= is a
leftover hook in =main/CMakeLists.txt=). Do not treat =sniffer.c= as shipping
firmware.

How to flash the firmware onto the TX and RX packs:

#+BEGIN_SRC bash
IEM_NODE=TX idf.py fullclean flash
IEM_NODE=RX idf.py fullclean flash
#+END_SRC

=main/CMakeLists.txt= refuses to build if =IEM_NODE= is missing. That is
intentional so you do not flash the wrong image.

May need to build ESP's libraries in the project root directory first:
#+BEGIN_SRC bash
cd ESP32IEM_Pack
get_idf
#+END_SRC

** Firmware design philosophy

I did not start with a fixed architecture diagram. The philosophy below is what
*emerged* once the breadboard proved audio could move, and once ESP-NOW + I2S
constraints became real. Almost every choice in =main/tx.c=, =main/rx.c=, and
=main/rig_shared.h= is intentional --- latency, robustness, and keeping the
Wi-Fi task thin.

*** Explicit state machines (not a pile of flags)

TX and RX each run a small mode enum driven from =app_main= (=TX_MODE_*= /
=RX_MODE_*=): boot → idle/pairing → transmit/playback, with helpers like
=run_idling_state= / =run_transmitting_state= / =run_audio_playback_state=.

Why: pairing, link loss, and audio streaming are different contracts. A state
machine makes illegal transitions obvious (e.g. do not enqueue audio while still
advertising), keeps =recv_cb= from becoming a second control plane, and matches
how I already think about systems --- events in, one current mode out. Soft
reconnect (audio-sized frames from a known TX while still pairing) is a
*deliberate* exception with a named path (=try_soft_reconnect_from_audio=), not
an accidental fall-through.

*** Packet *size* is the type tag

On the wire there is no separate "opcode" header for the common path. Handlers
branch on =data_size=:

- pairing request ≈ =sizeof(pairing_req_packet_t)= (alias string)
- pairing ACK/NACK = 1 byte (=PAIR_ACK_LEN=; legacy =sizeof(pair_state_t)= also
  accepted on RX)
- audio = =sizeof(audio_packet_t)= (240 interleaved =int16= samples → 480 B)

Why: ESP-NOW already gives you length. Another type byte would cost payload
budget and another branch on every ~2.5 ms audio frame. Distinct struct sizes
make the hot path a few integer compares. Wrong-sized frames are ignored (with
rate-limited logs while pairing so a TX audio flood cannot spam the console at
~400 Hz).

*** Low overhead on the audio path (bitwise / packing / queues of pointers)

Audio is the budget that matters. Design choices that keep CPU and copies down:

- *Pack once.* I2S often delivers 32-bit slot words; TX shifts with =>>= 16= into
  =int16= PCM for the air format (PCM1808 / slot width forced this; the shift is
  the cheap conversion, not a float path).
- *Low-latency packets (this branch).* 240 samples @ 48 kHz = 2.5 ms/packet,
  ~400 pkt/s --- aggressive vs the old 7.5 ms / ~133 pkt/s breadboard-stable
  choice. Relies on =send_cb= pacing + RX pointer-pool. If ESP-NOW drops climb,
  step toward 288 samples (3 ms) before abandoning the ~10 ms e2e target.
- *Pointer-pool jitter buffer on RX.* Queues carry =audio_packet_t *= into a
  fixed pool, not full packet copies on every hop; playback pins to another core
  with a short pre-buffer (2 packets / 5 ms) so the first I2S write does not
  underrun. PCM5102: close =SW2= (FLT=IIR) for ~0.4 ms less DAC filter delay.
- *Keep heavy work off Wi-Fi callbacks.* Pairing work is queued to the state
  machine; =esp_now_add_peer= and I2S enable happen in safe contexts. Send
  pacing waits for =send_cb= so bursts do not disorder callbacks / =NO_MEM=.
- *Silence is zeros, not a skipped send* while transmitting, so the RX timeout
  logic sees a live link instead of a mysterious gap.

None of this was "optimize everything." It was: find the hot path, make the
common case boring and cheap, and put complexity in pairing / reconnect where
milliseconds matter less than correctness.

The *32U* module has a U.FL connector and *no PCB antenna*. =ANT1= is a BOM /

*** Analog (PCM5102 datasheet vs experiments)

The PCM5102 datasheet analog network for a ~10 kOhm load is already on the DAC
sheet (=R16=/=R17= 470 ohm, =C20=/=C21= 2.2 nF):

=OUTL/OUTR -> 470 ohm series -> =DAC_OUT=, with *2.2 nF from that node to GND*.

That ~10 kOhm load is mainly the *dual-gang pot* (10 kOhm), which sits right after
=DAC_OUT=. Keep the pot; leave the 470 ohm + 2.2 nF alone unless you change that
load a lot.

MAX97220*A* (and B/E) has *no* fixed Zin --- input resistance is your external
=RIN= (=AV = -RF/RIN=; RF typically 4.7 kOhm--100 kOhm). =RIN= is now *47 kOhm*
and =RF= is *4.7 kOhm*, and all eight parts are *populated* (no longer DNP).
Changing =RF= does *not* require retuning the DAC RC. See
[[*Volume, gain, and audible-band response][Volume, gain, and audible-band response]]
for why those values, and for the loudness math.
MAX97220*C*/*D* are *fixed +6 dB* (internal Rs); wrong if you want resistor-set
max loudness.

The experimental 1 kOhm / 10 ohm pad on =vol_ctrl= is *DNP*, with a short across
the 1 kOhm positions so an empty series part does not open the audio path. You
do *not* need that pad for level safety --- filtered =DAC_OUT= can feed the pot
directly (see =docs/hardware_revisions.org=).

*** Volume, gain, and audible-band response

All numbers here are reproduced on the schematic itself: the gain budget is on
the =amp= sheet, the filter audit is on the =dac= sheet.

**** Gain budget

Two resistor groups set the gain, and each group must stay internally matched or
the pseudo-differential balance (CMRR) is lost:

| Group  | Parts             | Value  | Role             |
|--------+-------------------+--------+------------------|
| =RF=   | R1, R3, R9, R10   | 4.7 k  | gain numerator   |
| =RIN=  | R2, R4, R5, R6    | 47 k   | gain denominator |

R1/R10 are the feedback resistors, R3/R9 are the matching shunts on the =IN+=
legs. R4/R2 are the input series resistors, R5/R6 their matching partners.

| Stage                              | Expression       |     dB |
|------------------------------------+------------------+--------|
| =R16=/=R17= + =VR1= divider        | 10k / (470 + 10k) |  -0.40 |
| Amp gain =RF/RIN=                  | 4.7k / 47k        | -20.00 |
| *Total*                            |                   | *-20.40* (x0.0955) |

The PCM5102A puts out *2.1 Vrms* at full scale, so with =VR1= wide open:

: Vout = 2.1 x 0.0955 = 0.201 Vrms at J1

**** Why 47 k and not the datasheet's 10 k

The 10 kOhm in the typical application circuit is a generic reference, not a
design for a 2.1 Vrms source driving sensitive IEMs. Raising =RIN= fixes three
things at once, and raising the pot value instead would only fix the second:

1. *Gain.* Unity gain hands the DAC's full 2.1 Vrms straight to the IEM.
2. *Pot taper.* A 10 kOhm =RIN= loads a 10 kOhm pot 1:1, which squashes the taper
   and makes the top of the range behave badly. 47 k gives a 4.7x ratio.
3. *Bass rolloff.* The coupling caps work against =RIN=, not against the pot. At
   10 k the corner sat at *33.9 Hz*, costing *-5.87 dB at 20 Hz*. At 47 k with
   the 1 uF caps it is 3.4 Hz.

Do *not* also fit a larger pot. 47 k =RIN= with a 50 k pot puts the loading ratio
back at ~1:1 and undoes point 2.

**** Loudness math

: Peak SPL = IEM sensitivity (dB/Vrms) + 20 x log10(Vout)

Manufacturers quote sensitivity two different ways. If yours is in *dB/mW* you
must convert to *dB/Vrms* first, using the headphone impedance Z in ohms:

: dB/Vrms = dB/mW + 10 x log10(1000 / Z)

That falls out of =P = V^2/Z=. One volt into Z ohms delivers =1000/Z= milliwatts,
and converting a power ratio to dB is =10 x log10=. At Z = 1000 ohms the two
figures are identical; below that dB/Vrms is the larger number.

| IEM               | Spec               |     Z | dB/Vrms | Peak SPL at max volume |
|-------------------+--------------------+-------+---------+------------------------|
| KZ ZS10 Pro X     | 112 dB (as dB/mW)  | 29 R  |   127.4 | 113.4 dB               |
| KZ, +3 dB tol.    | 115 dB/mW          | 29 R  |   130.4 | 116.4 dB               |
| Moondrop Aria     | 122 dB/Vrms        | 32 R  |   122.0 | 108.0 dB               |

*Caveat worth checking yourself:* KZ publishes "112±3dB" without stating the
reference. Treating it as dB/mW is the conservative reading (it makes the IEM
127 dB/Vrms, i.e. louder). If it is actually already dB/Vrms, max volume is a
much tamer 98 dB. Moondrop's figure is unambiguous --- they state dB/Vrms.

**** Filter audit

Only *two* reactive components sit in the audio path. Everything else in the
chain is resistive, and because the MAX97220 uses a ground-referenced
DirectDrive output, =J1= needs no output coupling cap and has none --- so there
is no output pole at all.

| # | Network                                | Type            | Corner   | Error in band     |
|---+----------------------------------------+-----------------+----------+-------------------|
| 1 | =R16=/=R17= 470 R with =C20=/=C21= 2.2 nF | reconstruction  | 161 kHz  | -0.07 dB @ 20 kHz |
| 2 | =C1=/=C4= 1 uF into =RIN= 47 k         | input coupling  | 3.4 Hz   | -0.12 dB @ 20 Hz  |

Network 1 is loaded by =VR1=, so the resistance setting that corner is 470 R in
parallel with the 10 kOhm pot, which is 449 R:
=fc = 1 / (2 x pi x 449 x 2.2n) = 161 kHz=.

Network 2 sees =RIN= directly, because the inverting input is a virtual ground:
=fc = 1 / (2 x pi x 47k x 1u) = 3.4 Hz=.

=C2=/=C3= form the matching leg on the =IN+= inputs. They carry no signal, so
they set noise and CMRR rather than frequency response. They are *1 uF as well*:
the two halves of each pseudo-differential pair have to track at low frequencies
or CMRR degrades down there, so all four caps must be changed together.

Resulting deviation across the audible band:

| Frequency | Deviation |
|-----------+-----------|
| 20 Hz     | -0.12 dB  |
| 30 Hz     | -0.06 dB  |
| 50 Hz     | -0.02 dB  |
| 100 Hz    |  0.00 dB  |
| 1 kHz     |  0.00 dB  |
| 10 kHz    | -0.02 dB  |
| 20 kHz    | -0.07 dB  |

For comparison, the old 10 k =RIN= gave -5.87 dB at 20 Hz and -3.56 dB at 30 Hz,
and 47 k with the original 0.47 uF caps gave -0.53 dB at 20 Hz.

**** Why 1 uF and not 0.47 uF

Flatness is the smaller half of the reason. The bigger one is distortion: Class
II ceramics (X7R and friends) are nonlinear, and the distortion they contribute
scales with the signal voltage developed *across* the cap. A coupling cap only
develops appreciable voltage near its corner, so the low end is exactly where a
ceramic misbehaves.

| C_in    | Xc @ 20 Hz | Signal across cap @ 20 Hz | @ 50 Hz | Corner  |
|---------+------------+---------------------------+---------+---------|
| 0.47 uF | 16.9 kOhm  | 33.9%                     | 14.3%   | 7.20 Hz |
| 1 uF    | 8.0 kOhm   | 16.7%                     | 6.8%    | 3.39 Hz |
| 2.2 uF  | 3.6 kOhm   | 7.7%                      | 3.1%    | 1.54 Hz |

At 0.47 uF a third of the 20 Hz signal sat across the dielectric. 1 uF halves
that. 2.2 uF would halve it again, but a 1.54 Hz corner passes more subsonic
rumble and DC drift into the amp for +0.09 dB of flatness, so 1 uF is the stop
point --- conventional practice puts a coupling corner around 3--5 Hz.

All four are the same =C_0805_2012Metric_Pad1.18x1.45mm_HandSolder= footprint as
before, so this is a value-only change with no layout impact. Specify *X7R or
better* and avoid Y5V/Z5U, whose capacitance collapses with temperature and bias
and would move the corner around unpredictably.

**** Changing the gain later

Raise =RF= (R1, R3, R9, R10) together and leave =RIN= alone:

| =RF=  | Gain      | Vout      | KZ ZS10 Pro X | Moondrop Aria |
|-------+-----------+-----------+---------------+---------------|
| 4.7 k | -20.4 dB  | 0.201 Vrms | 113.4 dB     | 108.0 dB      |
| 10 k  | -13.8 dB  | 0.427 Vrms | 120.0 dB     | 114.6 dB      |

Do not go past 10 k. Risk of hearing damage climbs steeply above ~120 dB SPL.
Since all eight resistors share one 0805 hand-solder footprint, gain is chosen at
build time --- there is no need for spare DNP trim positions on the board.

**** Why =D1= moved to the unswitched side

=D1= is an =SP0503BAHT=, a four-line TVS array: one common anode on GND and three
independent cathodes. Two of those cathodes clamp =D+= and =D-= and did not move.
The third was clamping =+5V=, which is the rail *after* =SW4=.

The point of a TVS is to shunt a static discharge to ground before it reaches
anything fragile. The place a discharge actually enters this board is the USB-C
connector, because that is the only conductor a person can touch. With the clamp
behind the power switch, flipping =SW4= to OFF disconnects the clamp from the
connector and leaves =J6='s VBUS pin unprotected --- so the board is *least*
protected in the state where it is most likely to be handled, unplugged, and
tossed in a bag. Moving the clamp to =VBUS_RAW= puts it on the exposed pin
permanently.

This does *not* compromise the off state you asked for. A TVS is an open circuit
below its standoff voltage; it conducts only during a transient. =SW4= still
breaks the rail feeding =U4=, =U5=, and everything downstream, so OFF is still
genuinely dead --- the only thing now sitting on the connector side is a diode
that draws leakage in the nanoamp range.

Still true / do not "fix" into something else:

- I2S GPIOs stay IO33 / IO32 / IO25 (breadboard + =square_wave_test.c=).
- USB-C =Rd= 5.1 k on CC1/CC2 is correct for a UFP / power-bank sink.
- CP2102C =R25= 22.1 k / =R26= 47.5 k is the *VBUS* divider, not a =VIO= divider.
- Amp gain resistors are *populated*, not DNP. An unpopulated =RF= leaves the
  MAX97220 with no feedback path, so it runs open loop and slams to the rails ---
  that is louder and less safe than a wrong gain, not quieter.
- LM3940 in SOT-223 will get hot at 5 V -> 3.3 V under ESP TX + amp load --- copper pour / thermal vias at layout time.

** My first-board mistakes

 The list below is the stuff that I already made mistakes on. Listed so I can check it every time
 I move a part or add a hierarchical label.

*** 1. Rotating a symbol does not remap pin numbers

Pin 3 is still =EN= after a 270 degree rotate. KiCad only rotates the *drawing*
and the *sheet coordinates* of the pins around the symbol origin. Hierarchical
labels and wires that stay put will attach to whichever pin rotated into that
spot.

After any rotate: click each pin, read the name, then move the label onto
*that* pin. Do not assume "left side is still EN."

*** 2. Hierarchical labels connect through wires, not vibes

A label sitting near a pin is not connected. ERC and the ratsnest follow
*wires and pin ends*. After a rotate, a label can look "on" the chip and still
sit on empty space or on the wrong pin (=ESP_IO0= on =EN=, =BCK= on =DEMP=,
=SHDN_SIGNAL= on =C1N=).

Triple-check every hierarchical label against the *pin name*, not the side of
the box.

*** 3. Same-ish names are different pins

| You meant                         | Easy to hit instead      | What happens                              |
|-----------------------------------+--------------------------+-------------------------------------------|
| PCM5102 =BCK= / =DIN= / =LRCK=    | =DEMP= / =XSMT= / =FMT=  | DAC never gets PCM; clocks toggle config  |
| PCM5102 =OUTL= / =OUTR=           | =LDOO= / =VNEG=          | Analog filter on the 1.8 V LDO pin        |
| MAX97220 =~{SHDN}=                | =C1N= (charge-pump cap)  | Volume switch does not mute; VSS breaks   |
| MAX97220 =OUTL= / =OUTR=          | =PVSS= / =SVSS= (BIAS)   | Jack sits on the charge-pump rail         |
| ESP =TXD0= / =RXD0=               | =SENSOR_VN= / empty      | USB-C UART programming dies               |
| I2S                               | I2C                      | Wrong bus, wrong pins, wrong mental model |

Read the pin *name* in the status bar before you drop the label.

*** 4. Firmware GPIO numbers are the contract

=#define BCK_PIN 33= is IO33 on the module, period. Do not "clean up" the
schematic onto IO18/19/23 unless you change the C defines too. Label =DIN= on
the DAC is the ESP's *DOUT*.

*** 5. The footprint field is a part you have to buy and solder

If the field says =R_0201_0603Metric=, you will get 0201s. Bulk 10 uF parts
basically do not exist in 0201, and you will not hand-assemble them. For a
hand-built proto use the =*_HandSolder= 0805 footprint (longer iron pads), then
*Update PCB from Schematic* so the copper matches.

*** 6. DNP does not delete the net

KiCad "Do not populate" still leaves the schematic wires. If you DNP a *series*
resistor, the path goes open unless you add a solder-bridge / short. If you DNP
a *shunt*, leaving the pads empty is correct (no short to GND).

*** 7. 32U vs 32E, A vs D, datasheet vs doodle

- *32U* = U.FL only. *32E/32D* = PCB antenna. Pick one and BOM the matching RF
  parts.
- *MAX97220A/B/E* = external gain (=RF/RIN=). *C/D* = fixed +6 dB. Letter matters.
- Prefer the datasheet application circuit (470 ohm + 2.2 nF here) over a pad
  you tried on the bench, unless you measured why the pad is better.

*** 9. Power and analog will buzz on a breadboard

Long jumpers, no ground plane, and an ESP32 radio next to a DAC is a buzz/hiss
machine. That does not automatically mean the circuit is wrong. A PCB with
short I2S, local decoupling, and a solid GND will almost certainly be quieter.
It is not guaranteed to be silent on the first spin.
