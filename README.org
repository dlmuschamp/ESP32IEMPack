* What this is

A two-pack wireless in-ear monitor (IEM) prototype:

- *TX pack* — ESP32-WROOM + PCM1808 ADC captures line/stereo PCM and
  streams it over *ESP-NOW v2*.
- *RX pack* — ESP32-WROOM + PCM5102 DAC plays the stream into a
  headphone amp / IEMs (~ESP-NOW → ESP32 → I2S → PCM5102 → volume pot
  → MAX97220A → 3.5 mm jack~).

This repo is the firmware (ESP-IDF, C, FreeRTOS) plus KiCad hardware
work. The breadboard plays audio. The KiCad project in
=KiCad/RX_SKETCHES/= is that breadboard transferred onto hierarchical
sheets — not a finished layout. There is *no display on this version*.

* Findings (2026-08-21 sound-profile night) — CER summary

** Claim: Soft-LPF on *digital* audio is ruled out

- *Evidence:* ~RX_DAC_TEST~ sine_8k / chirp crisp; ~TX_TONE~ over air into
  shipping RX also crisp; direct laptop→IEMs bright.
- *Reasoning:* Known-bright PCM survives packing + ESP-NOW + PCM5102.
  Dullness that appears only with the real PCM1808 / jack path is not
  “ESP-NOW filtering highs.”

** Claim: Real-music dullness + buzz is analog / breadboard / level

- *Evidence:* Real music much quieter than digital tones; laptop <30% ≈
  noise; gain×8 louder but more crackle; 1 µF VIN caps marginal; shorter
  3.5 mm cable did not kill buzz; open GND dropped center (vocals/bass).
- *Reasoning:* Weak ADC level sits near the noise floor; Dupont / shared
  ground / breakout limits look like LPF+buzz. PCB layout is the next
  falsification — not more firmware EQ.

** Claim: TX_TONE steady ticks were mostly a FreeRTOS pace bug

- *Evidence:* ~pdMS_TO_TICKS(8)~ == 0 at ~FREERTOS_HZ=100~; RX queue drops
  flooded; ~esp_timer~ 7.5 ms pace fixed most ticks (code in
  ~main/debugging/~).
- *Reasoning:* Shipping TX paces via blocking I2S reads; tone mode had
  to invent realtime pacing.

** Claim: Buzz may be a breadboard limitation (plus possible USB ground loop)

- *Evidence:* Persists with shorter cable; can improve when TX is on a
  power bank vs same-laptop USB+jack; digital path without ADC is clean.
- *Reasoning:* Ground loops and long analog jumpers are expected on a
  bench; a short-trace PCB with datasheet coupling/decoupling is the
  proper A/B.

* Hardware (bring-up + RX KiCad)

** Roles

| Pack | MCU | Audio IC | Role |
|------+-----+----------+------|
| TX | ESP32-WROOM-32U (ext antenna) | PCM1808 | I2S master RX ← ADC |
| RX | ESP32-WROOM-32U + U.FL | PCM5102 | I2S master TX → DAC |

** RX hierarchical sheets (signal order)

1. =pwr_mgmt= — USB-C (CC pulldowns), CP2102C UART bridge, LM3940 5 V → 3.3 V
2. =esp_rx= — ESP32-WROOM-32U + =ANT1= (U.FL pigtail / 2.4 GHz antenna)
3. =dac= — PCM5102
4. =vol_ctrl= — dual-gang log pot + 0% switch
5. =amp= — MAX97220A to the 3.5 mm jack

** Firmware I2S map (do not "improve" these GPIOs)

These match the working breadboard and =main/debugging/square_wave_test.c=:

| Hierarchical label | ESP32 GPIO | Firmware name |
|--------------------+------------+---------------|
| =BCK=              | IO33       | =BCK_PIN= |
| =LRCLK=            | IO32       | =LRCK_PIN= |
| =DIN=              | IO25       | =DOUT_PIN= (ESP data *out* to the DAC data *in*) |

UART programming: =TXD= = TXD0/IO1, =RXD= = RXD0/IO3. Auto-program
straps: =ESP_EN= = EN, =ESP_IO0= = IO0.

** Antenna (=ANT1= on =esp_rx=)

The *32U* module has a U.FL connector and *no PCB antenna*. =ANT1= is a
BOM / documentation part: a *2.4 GHz, 50 Ω antenna on a U.FL / IPEX
pigtail* that mates to the connector already on the module. It is not
wired to a GPIO. It has no PCB footprint — you buy the pigtail, you do
not etch an antenna.

If you want an on-board antenna later, that is a different module
(WROOM-32E / 32D), not a missing copper pour on the 32U.

** I2S notes that matter

- PCM1808 in slave mode wants *64 BCK/frame* → configure *32-bit stereo*
  Philips slots. 16-bit slots (32 BCK/frame) → silent ADC.
- MCLK ×256 is a valid PCM1808 ratio and matched our working builds.
  A casual jump to 24-bit data + MCLK×384 broke a known-good path —
  only revisit with a rollback bin ready.
- PCM5102: FMT low = I2S; DEMP low/NC = de-emphasis off.
- PCM1808 VIN: AC-couple with ~1 µF (TI app circuit; internal ~60 kΩ
  sets ~2.7 Hz HPF). Do *not* add an external 60 kΩ for that formula.

** Power (the lesson that unlocked pairing)

Marginal power on the TX pack looks exactly like "RF is broken":

- TX on weak battery → often never receives pairing ads.
- TX on laptop USB → pairs; opening ~idf.py monitor~ / pyserial can
  still *reboot* the board via CP2102 DTR/RTS → audio drops.
- Two decent USB power banks on *both* packs → instant pair, louder
  audio (more supply noise / crackle without caps).

For listening tests, prefer dedicated supplies. Use USB for flash and
short log peeks. Add bulk electrolytics + 0.1 µF at codec rails before
chasing "digital crackle."

** Pack architecture (mechanical first)

Plastic shell ~Altoids *size* (not metal tin). Antenna and volume pot on
*opposite corners of the top face*; USB-C / coiled battery power enter
at the *bottom* (battery off-pack); 3.5 mm IEM jack on a *side face*.
Keep pot traces away from the antenna keepout. No DIY impedance matching
— the module already brings 50 Ω to U.FL.

** RX DAC / line toward pot (PCM5102)

- Follow the TI PCM5102 datasheet *OUTL / OUTR* example aimed at a
  *LINE IN* into a *~10 kΩ* load — *page 27* (series R + shunt C on both
  channels). That is =R16=/=R17= 470 Ω + =C20=/=C21= 2.2 nF toward
  =PRE_POT=.
- Feed PRE_POT into a *10 kΩ log dual-gang* pot; wipers =POST_POT= drive
  the headphone amp.
- The experimental 1 kΩ / 10 Ω pad on =vol_ctrl= is *DNP*, with a short
  across the 1 kΩ positions so an empty series part does not open the
  audio path.

** Amp gain resistors (leave for later)

MAX97220A voltage gain is *fixed +3.5 dB* on the A variant. Input
network resistors (GROUP A / GROUP B on the paper desk schematic) stay
*DNP* on hand-built protos so you can try values. Populate them (start
10 kΩ) only if you order a fully assembled board. Use a MAX97220*D* if
you want resistor-programmed gain.

** TX ADC (PCM1808)

- Series *~1 µF* into VINL / VINR; AGND–DGND under the package; VREF /
  VCC / VDD local 0.1 µF (+ bulk where the datasheet shows).
- Match breakout reality: many modules already have rail caps; VIN
  coupling is what was often missing on the breadboard.

** Hand assembly / passives

- Default resistors and most ceramic caps to *0805 HandSolder*
  footprints (longer pads) for a first hand-built proto.
- *0603* is doable with practice; *0402* / *0201* are a pain — avoid for
  hand assembly.
- ICs, USB-C, 3.5 mm jack, pot, SOT-23, and the WROOM module *cannot*
  become 0805 — those packages are the part. TQFN / WQFN still need hot
  air / hot plate or a board house.
- Renaming footprint *fields* in the schematic does not resize copper.
  After footprint or net changes: *Update PCB from Schematic*.

** Datasheet audit (known issues; fixes live on PR #2)

Checked against PCM5102 / PCM5102A, MAX97220A, LM3940, CP2102C, and
ESP32-WROOM-32U notes. These are the mistakes found on the transferred
schematic. The schematic fixes are on branch
=cursor/rx-schematic-wip-fixes-738e= (PR #2) — review before merging.

| Issue | Spec | Intended fix |
|-------+------+--------------|
| DAC 470R+2.2nF on =LDOO= / not on =OUTL=/=OUTR= | Filter on pins 6/7; =LDOO= needs 0.1 µF to GND | Rewire filter to outs; add =C28= on =LDOO= |
| Flying cap off =CAPP=/=CAPM= pin ends | 2.2 µF between pins 2 and 4 | Wire to actual pin ends |
| Headphone jack on =PVSS=/=SVSS= | Those are charge-pump / BIAS rails | Tip==OUTL=, Ring==OUTR=, Sleeve=GND; =C29= on =PVSS= |
| CP2102C =VIO= left off =VDD= | =VIO= = I/O rail @ 3.3 V | Tie =VIO= to =VDD=; pull =~{RST}= up |
| LM3940 missing 0.47 µF Cin | Datasheet Cin + 33 µF low-ESR Cout | Add Cin; prefer tantalum on Cout if ceramic ESR is too low |
| ESP =IO0= with no pull-up | Strap high for normal boot | 10 k to +3V3 |

Still true / do not "fix" into something else:

- I2S GPIOs stay IO33 / IO32 / IO25.
- USB-C =Rd= 5.1 k on CC1/CC2 is correct for a UFP / power-bank sink.
- Amp input 10 k resistors stay DNP on a hand-built proto.
- LM3940 in SOT-223 will get hot at 5 V → 3.3 V under load — copper /
  thermal vias at layout time.

* Common KiCad / first-board mistakes

Check this list every time you move a part or add a hierarchical label.

** 1. Rotating a symbol does not remap pin numbers

Pin 3 is still =EN= after a 270° rotate. KiCad only rotates the
*drawing* and the *sheet coordinates* of the pins around the symbol
origin. Hierarchical labels and wires that stay put will attach to
whichever pin rotated *into that spot*.

A schematic "group" (or selecting everything and moving together) only
keeps relative geometry. It does *not* permanently glue a label to a
pin name. After any rotate: click each pin, read the name in the status
bar, then put the label on *that* pin. Do not assume "left side is
still EN."

** 2. Hierarchical labels connect through wires, not vibes

A label sitting near a pin is not connected. ERC and the ratsnest follow
*wires and pin ends*. After a rotate, a label can look "on" the chip and
still sit on empty space or on the wrong pin (=ESP_IO0= on =EN=, =BCK=
on =DEMP=, =SHDN_SIGNAL= on =C1N=).

** 3. Same-ish names are different pins

| You meant                      | Easy to hit instead     | What happens |
|--------------------------------+-------------------------+--------------|
| PCM5102 =BCK=/=DIN=/=LRCK=     | =DEMP=/=XSMT=/=FMT=     | DAC never gets PCM |
| PCM5102 =OUTL=/=OUTR=          | =LDOO=/=VNEG=           | Filter on the 1.8 V LDO pin |
| MAX97220 =~{SHDN}=             | =C1N= (charge-pump)     | Mute broken; VSS breaks |
| MAX97220 =OUTL=/=OUTR=         | =PVSS=/=SVSS= (BIAS)    | Jack on charge-pump rail |
| ESP =TXD0=/=RXD0=              | =SENSOR_VN= / empty     | USB-C UART programming dies |
| I2S                            | I2C                     | Wrong bus entirely |

** 4. Firmware GPIO numbers are the contract

=#define BCK_PIN 33= is IO33 on the module, period. Do not "clean up"
the schematic onto other GPIOs unless you change the C defines too.

** 5. The footprint field is a part you have to buy and solder

If the field says =R_0201_…=, you will get 0201s. For hand-built protos
use =*_HandSolder= 0805, then *Update PCB from Schematic*.

** 6. DNP does not delete the net

KiCad "Do not populate" still leaves the wires. DNP a *series* resistor
→ path goes open unless you add a solder bridge. DNP a *shunt* → empty
pads are fine.

** 7. 32U vs 32E, A vs D, datasheet vs doodle

- *32U* = U.FL only. *32E/32D* = PCB antenna.
- *MAX97220A* is not *MAX97220D* (gain mode).
- Prefer the datasheet app circuit over a bench pad unless you measured why.

** 8. The =.kicad_pcb= is not a board until it has Edge.Cuts and tracks

A pile of footprints with a ratsnest is a placeholder. Do not send it to
a fab.

** 9. Power and analog will buzz on a breadboard

Long jumpers + no ground plane + ESP32 radio next to a DAC is a
buzz/hiss machine. That does not automatically mean the circuit is wrong.

** 10. Keep the project notes honest

If the schematic is USB-C + LDO and no display, =README.org= must not
still say LiPo + TFT, Arduino, or a HAL that is not in the tree.

* Firmware overview

** Build / flash (ESP-IDF)

~IEM_NODE~ is *configure-time*. Wrong node + stale build = wrong image
on the wrong pack. =main/CMakeLists.txt= refuses to build if =IEM_NODE=
is missing — intentional.

#+begin_src bash
source ~/esp/esp-idf/export.sh   # or your IDF install

# Shipping transmitter / receiver
IEM_NODE=TX idf.py reconfigure build
IEM_NODE=TX idf.py -p /dev/ttyUSB0 flash

IEM_NODE=RX idf.py reconfigure build
IEM_NODE=RX idf.py -p /dev/ttyUSB0 flash

# Archived isolation builds (main/debugging/)
IEM_NODE=RX_DAC_TEST idf.py reconfigure build flash
IEM_NODE=TX_TONE idf.py reconfigure build flash
IEM_NODE=TX_BUZZ_DEBUG idf.py reconfigure build flash
#+end_src

** Protocol sketch

1. RX advertises a short ~IEM_RX_…~ alias (broadcast, and unicast to last
   TX when known).
2. TX queues the request, ~esp_now_add_peer~, ACKs ~PAIR_SUCCESS~, then
   streams ~audio_packet_t~.
3. If ACKs are starved by audio, RX *soft-joins* on a correctly sized
   audio packet (app-layer proof of delivery).
4. TX may clear a dead peer on MAC send-fail / timeout so it can idle
   and accept a new advert.
5. Prefer not starting DAC playback on a lone 1-byte ~0x01~ ACK (any
   nearby ESP can spoof that and leave RX mute-and-not-advertising).

** FreeRTOS / dual core (what you bump into first)

- Wi‑Fi / ESP-NOW callbacks run in the Wi‑Fi task — keep them short
  (queue work; do not ~esp_now_add_peer~ / heavy I2S in the callback).
- Audio capture (TX) and playback (RX) are pinned to core 1 with a
  dedicated stack size (~AUDIO_TASK_STACK~).
- Pointer pools + FreeRTOS queues bound latency (drop-oldest under
  load) instead of unbounded buffering.

* Learning path (recommended order)

1. Blink / UART logging on ESP-IDF (prove the toolchain).
2. Square wave → PCM5102 (prove DAC + I2S pins).
3. PCM1808 capture → log peaks (prove ADC clocks / bit packing).
4. Tiny ESP-NOW ping, then grow to v2 payload size.
5. *Fix power* so both packs can transmit Wi‑Fi without brownout.
6. Pairing FSM + reconnect.
7. Digital tone isolation (DAC-only, then TX tone over air).
8. Only then: PCB layout / amp / timbre on a real board.

Reading datasheets is not optional on this project — the PCM1808 BCK
rule alone is a multi-hour footgun if you skip §serial audio interface.
