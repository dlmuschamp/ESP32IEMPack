* ESP32 Wireless IEM Pack

A first-pass wireless in-ear monitor (IEM) system: one ESP32 transmitter pack
and one ESP32 receiver pack. The RX path is ~ESP-NOW -> ESP32 -> I2S ->
PCM5102 DAC -> volume pot -> MAX97220A headphone amp -> 3.5 mm jack~.

This repo is a work in progress. The breadboard version plays audio. The KiCad
project in =KiCad/RX_SKETCHES/= is that breadboard transferred onto hierarchical
sheets --- not a finished layout. There is *no display on this version*.

** Firmware

All application code is *C*. It runs on *FreeRTOS* under *ESP-IDF*, using the
related Espressif libraries (ESP-NOW / Wi-Fi, I2S, ADC, LEDC, NVS). There is
*no Arduino* in this project. There is *no hardware abstraction layer* --- the
firmware calls ESP-IDF APIs directly.

- =main/tx.c= :: Transmitter. Done for this version (ESP-NOW, ADC pot, LED,
  audio packet path).
- =main/rx.c= :: Receiver entry. Still the thin side of the pair; build with
  =IEM_NODE=RX= when you flash it.
- =main/square_wave_test.c= :: Bench I2S tone used to prove the DAC path.
- =main/rig_shared.h= :: Shared packet and state types for TX and RX.

A packet sniffer / monitor node was an early idea. It is *not* part of this
version. It could come back later as a future extension (=IEM_NODE=MON= is a
leftover hook in =main/CMakeLists.txt=). Do not treat =sniffer.c= as shipping
firmware.

Build a node after exporting the target:

#+BEGIN_SRC bash
IEM_NODE=TX idf.py build
# IEM_NODE=RX when flashing the receiver
#+END_SRC

=main/CMakeLists.txt= refuses to build if =IEM_NODE= is missing. That is
intentional so you do not flash the wrong image.

** Hardware (RX 1.0.0 KiCad)

Hierarchical sheets, in signal order:

1. =pwr_mgmt= --- USB-C (CC pulldowns), CP2102C UART bridge, LM3940 5 V -> 3.3 V
2. =esp_rx= --- ESP32-WROOM-32U + =ANT1= (U.FL pigtail / 2.4 GHz antenna)
3. =dac= --- PCM5102
4. =vol_ctrl= --- dual-gang log pot + 0% switch
5. =amp= --- MAX97220A to the 3.5 mm jack

*** Firmware I2S map (do not "improve" these GPIOs)

RX contract is =main/rx.c= on branch =main= (=DOUT_PIN 25=). TX uses
=DIN_PIN 35= on the *transmitter* board only.

| Hierarchical label | ESP32 GPIO | Firmware name                                      |
|--------------------+------------+----------------------------------------------------|
| =BCK=              | IO33       | =BCK_PIN=                                          |
| =LRCLK=            | IO32       | =LRCK_PIN=                                         |
| =DOUT=             | IO25       | =DOUT_PIN= (ESP *out* -> PCM5102 pin *DIN*)        |

Hardware change log (what / why / evidence): =docs/hardware_revisions.org=.

UART programming: =TXD= = TXD0/IO1, =RXD= = RXD0/IO3. Auto-program straps:
=ESP_EN= = EN, =ESP_IO0= = IO0.

*** Antenna (=ANT1= on =esp_rx=)

The *32U* module has a U.FL connector and *no PCB antenna*. =ANT1= is a BOM /
documentation part: a *2.4 GHz, 50 ohm antenna on a U.FL / IPEX pigtail* that
mates to the connector already on the module. It is not wired to a GPIO. It has
no PCB footprint --- you buy the pigtail, you do not etch an antenna.

If you would rather have an on-board antenna later, that is a different module
(WROOM-32E / 32D), not a missing copper pour on the 32U.

*** Analog (PCM5102 datasheet vs experiments)

The PCM5102 datasheet analog network for a ~10 kOhm load is already on the DAC
sheet (=R16=/=R17= 470 ohm, =C20=/=C21= 2.2 nF):

=OUTL/OUTR -> 470 ohm series -> PRE_POT=, with *2.2 nF from that node to GND*.

The MAX97220A input impedance is also about *10 kOhm*, so that filter is the
right starting point. The experimental 1 kOhm / 10 ohm pad on =vol_ctrl= is
*DNP*, with a short across the 1 kOhm positions so an empty series part does
not open the audio path. You do *not* need that pad for level safety if the
pot and amp gain are enough --- filtered =DAC_OUT= can feed the pot directly
(see =docs/hardware_revisions.org=).

MAX97220A voltage gain is *fixed +3.5 dB*. Input network resistors =R1=--=R6=,
=R9=, =R10= are *DNP* on hand-built protos so you can try values. Populate them
(start 10 kOhm) only if you order a fully assembled board. Use a MAX97220*D* if
you want resistor-programmed gain.

*** Hand assembly

Every schematic resistor and capacitor now uses the KiCad *0805 hand-solder*
footprint (longer pads):

- =Resistor_SMD:R_0805_2012Metric_Pad1.20x1.40mm_HandSolder=
- =Capacitor_SMD:C_0805_2012Metric_Pad1.15x1.40mm_HandSolder=

Buy 0805 parts. ICs, the USB-C jack, the 3.5 mm jack, the pot, SOT-23
transistors, and the WROOM module *cannot* become 0805 --- those packages are
the part. TQFN / WQFN still need a hot plate, hot air, or a board house.

The =.kicad_pcb= footprint *names* were renamed, but the copper pads are still
the old 0201 geometry until you *Update PCB from Schematic* in KiCad.

*** Datasheet audit (what was wrong, what we changed)

Checked against the PCM5102 / PCM5102A, MAX97220A, LM3940, CP2102C, and
ESP32-WROOM-32U hardware notes.

| Issue | Spec | Fix on this branch |
|-------+------+--------------------|
| DAC 470R+2.2nF on =LDOO= / not on =OUTL=/=OUTR= | Filter belongs on pins 6/7. =LDOO= pin 18 needs 0.1 uF to GND | Rewired =R16=/=R17= to =OUTL=/=OUTR=. Added =C28= 0.1 uF on =LDOO= |
| Flying cap 2.54 mm off =CAPP=/=CAPM= pin ends | 2.2 uF between pins 2 and 4 | Extra wires to the actual pin ends |
| Headphone jack on =PVSS=/=SVSS= | Those are the -V charge-pump / BIAS rails. Audio is =OUTL=/=OUTR=. Sleeve is GND | Tip==OUTL=, Ring==OUTR=, Sleeve=GND. =C29= 1 uF =PVSS= to GND. =SVSS= tied to =PVSS= |
| CP2102C =VIO= left off =VDD= | =VIO= = I/O rail, same 3.3 V as the ESP | Wire =VIO= to =VDD=. =R29= 1 k pulls =~{RST}= to =VIO= |
| LM3940 missing 0.47 uF Cin | Datasheet: 0.47 uF on IN, 33 uF low-ESR on OUT | Added =C31= 0.47 uF. Keep =C23= 33 uF; if it is ceramic, ESR can be *too low* --- prefer tantalum or add ~0.5 ohm |
| ESP =IO0= with no pull-up | Strap should sit high for normal boot | =R30= 10 k to +3V3 |

Still true / do not "fix" into something else:

- I2S GPIOs stay IO33 / IO32 / IO25 (breadboard + =square_wave_test.c=).
- USB-C =Rd= 5.1 k on CC1/CC2 is correct for a UFP / power-bank sink.
- CP2102C =R25= 22.1 k / =R26= 47.5 k is the *VBUS* divider, not a =VIO= divider.
- Amp input 10 k resistors stay DNP on a hand-built proto.
- LM3940 in SOT-223 will get hot at 5 V -> 3.3 V under ESP TX + amp load --- copper pour / thermal vias at layout time.

** Common KiCad / first-board mistakes

First KiCad project, first C project, first ESP-IDF board, first time reading
IC spec sheets, first multi-IC audio schematic. The list below is the stuff
that already bit this schematic. Check it every time you move a part or add a
hierarchical label.

*** 1. Rotating a symbol does not remap pin numbers

Pin 3 is still =EN= after a 270 degree rotate. KiCad only rotates the *drawing*
and the *sheet coordinates* of the pins around the symbol origin. Hierarchical
labels and wires that stay put will attach to whichever pin rotated into that
spot.

After any rotate: click each pin, read the name, then move the label onto
*that* pin. Do not assume "left side is still EN."

*** 2. Hierarchical labels connect through wires, not vibes

A label sitting near a pin is not connected. ERC and the ratsnest follow
*wires and pin ends*. After a rotate, a label can look "on" the chip and still
sit on empty space or on the wrong pin (=ESP_IO0= on =EN=, =BCK= on =DEMP=,
=SHDN_SIGNAL= on =C1N=).

Triple-check every hierarchical label against the *pin name*, not the side of
the box.

*** 3. Same-ish names are different pins

| You meant                         | Easy to hit instead      | What happens                              |
|-----------------------------------+--------------------------+-------------------------------------------|
| PCM5102 =BCK= / =DIN= / =LRCK=    | =DEMP= / =XSMT= / =FMT=  | DAC never gets PCM; clocks toggle config  |
| PCM5102 =OUTL= / =OUTR=           | =LDOO= / =VNEG=          | Analog filter on the 1.8 V LDO pin        |
| MAX97220 =~{SHDN}=                | =C1N= (charge-pump cap)  | Volume switch does not mute; VSS breaks   |
| MAX97220 =OUTL= / =OUTR=          | =PVSS= / =SVSS= (BIAS)   | Jack sits on the charge-pump rail         |
| ESP =TXD0= / =RXD0=               | =SENSOR_VN= / empty      | USB-C UART programming dies               |
| I2S                               | I2C                      | Wrong bus, wrong pins, wrong mental model |

Read the pin *name* in the status bar before you drop the label.

*** 4. Firmware GPIO numbers are the contract

=#define BCK_PIN 33= is IO33 on the module, period. Do not "clean up" the
schematic onto IO18/19/23 unless you change the C defines too. Label =DIN= on
the DAC is the ESP's *DOUT*.

*** 5. The footprint field is a part you have to buy and solder

If the field says =R_0201_0603Metric=, you will get 0201s. Bulk 10 uF parts
basically do not exist in 0201, and you will not hand-assemble them. For a
hand-built proto use the =*_HandSolder= 0805 footprint (longer iron pads), then
*Update PCB from Schematic* so the copper matches.

*** 6. DNP does not delete the net

KiCad "Do not populate" still leaves the schematic wires. If you DNP a *series*
resistor, the path goes open unless you add a solder-bridge / short. If you DNP
a *shunt*, leaving the pads empty is correct (no short to GND).

*** 7. 32U vs 32E, A vs D, datasheet vs doodle

- *32U* = U.FL only. *32E/32D* = PCB antenna. Pick one and BOM the matching RF
  parts.
- *MAX97220A* is not *MAX97220D*. The letter is the gain mode.
- Prefer the datasheet application circuit (470 ohm + 2.2 nF here) over a pad
  you tried on the bench, unless you measured why the pad is better.

*** 8. The =.kicad_pcb= is not a board until it has Edge.Cuts and tracks

A pile of footprints with a ratsnest is a placeholder. After schematic net or
footprint changes, *Update PCB from Schematic*. Do not send that file to a fab.

*** 9. Power and analog will buzz on a breadboard

Long jumpers, no ground plane, and an ESP32 radio next to a DAC is a buzz/hiss
machine. That does not automatically mean the circuit is wrong. A PCB with
short I2S, local decoupling, and a solid GND will almost certainly be quieter.
It is not guaranteed to be silent on the first spin.

*** 10. Keep the project notes honest

If the schematic is USB-C + LDO and no display, =README.org= must not still say
LiPo + TFT, Arduino, or a HAL that is not in the tree.
